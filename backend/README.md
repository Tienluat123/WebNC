# PA2 places endpoint

This backend implements the adopted [GET /places contract](../docs/contract/endpoint.md).
It uses six explicitly synthetic places, not the class shared dataset or live business data.
No database, model or external places service is called.

## Setup and run

Use Node.js 22.18.x (verified locally: 22.18.0) and npm 10.9.3.
From the repository root, run `npm ci` to install dependencies from package-lock.json.
Express is pinned to 5.1.0. The lockfile was generated by the user's successful
`npm install` and should be included in the implementation commit.

Copy `.env.example` to `.env`. Set `PORT=3000` and set `CURSOR_SECRET` to a private
random value of at least 32 bytes. Generate a value locally with:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Keep the generated value in `.env`; never commit it. Reuse the same secret across
restarts so an old, signed cursor with a lost snapshot receives 410. Rotating the
secret invalidates existing signatures (400). No model API key is needed for this endpoint.

Run `npm start`, then visit:

```text
http://127.0.0.1:3000/places
http://127.0.0.1:3000/places?type=cafe&district=district-1&limit=1
http://127.0.0.1:3000/places?openNow=true&priceLevel=2
```

The server binds to loopback for local development. To continue a search, repeat
the same filters and limit and add the URL-encoded `nextCursor` as `cursor`.
Snapshots live in memory; a restart loses them. Retain revisions in durable storage
before relying on seamless pagination across production restarts or multiple workers.

## Code map

- `src/app.js`: Express factory and RFC 9457 error responses.
- `src/places.js`: validation, public field projection, filters and signed cursor paging.
- `src/fixtures.js`: synthetic records and menu data used only for the PA2 prototype.
- `src/server.js`: local startup and environment configuration.
- `test/places.test.js`: dependency-free service tests.
- `test/contract/places.test.js`: HTTP checks for success and all three problem types.

The service accepts an injected catalogue loader and clock so tests can exercise
data failures and expiry without real APIs, sleeps or production-only test routes.
